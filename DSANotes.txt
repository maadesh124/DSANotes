	-use while instead of for loop
	-update(increment or decrement) only one pointer in each iteration
	-use continue statements
	-make sure that right pointer always leads left pointer
	-make sure that direction of ptrs does not change(if left is moving from 0 to n-1 then the vale left should never decrease).
	-for each optimal ptr1 find optimal ptr2,let ptr2Opt be optimal val of ptr2 for ptr1 then find a constraint that says, optimal ptr2 for ptr1+1 comes after ptr2Opt in the direction of traversal.If there is no such constraint then the poblem cant be solved in O(n).also use the data obtained in finding Optimal ptr2 for ptr1 to find optimal ptr2 for ptr1+1.

4.When you need a data structure with O(1) insertion, deletion and O(1) search operation use HashMap.
	-Store element to be searched as key and its associated data as value 				in map,now search can be performd in O(1) ,worst case= O(n)
	-example : 2 sum problem -return i,j such that arr[i]+arr[j]==k(given num),
	-brute forsce:iterate through arr for each arr[i] check wheather k-arr[i] exits in arr
	-this takes O(n^2) time complexity. 
	-optimised oproach:Assuming each eleent occurs only once.store all elements of arr in map such that key=arr[i] ,value=i.
	-now perform search in map instead of array,time complexity=O(n) ,(worst case=O(n^2),this is very very rare)
	-reference="https://leetcode.com/problems/two-sum/submissions/1405949079/"

9.Extra pointer in Linked Lists 
	-Sometimes an extra pointer can be used with original pointer to find the required node
	-Example 1:middle element of Linked list can be found using slow and fast pointer, when fast pointer reaches end slow pointer is at middle node
	-Example 2:Nth last element:when two pointers with same speed but with initial offset of N can be used to find Nth last Element.fast pointer leads slow pointer by N nodes, when fast pointer is at end,slow is at N th last element
	-Loop problems :slow and fast pointers can be used to solve loop problems like "Length of the loop".When fast pointer leads slow pointer by N nodes then they will meet after N iterations(Speed of slow ptr is 1 Node/iteration,speed of fast is 2 node/iteration).

12.BackTracking is used to solve two types of problem "Permutation problem" and "Combination Problem"
	-when each index of answer takes multiple values it is Permutation problem.(requires for loop inside recursive function to iterate between all possible values).For each iteration put a particular value and call recursive function with next index then remove the added element and move to next iteration.ref:https://www.geeksforgeeks.org/write-a-c-program-to-print-all-permutations-of-a-given-string/
	-when each index of answer takes only 2 values(element at index of source is either picked or not picked) it is Cobination problem.recursive function is called only twice within it.For each index first pick the value ,call the recursive function then remove the added element and call the recursive function again.ref:https://takeuforward.org/data-structure/power-set-print-all-the-possible-subsequences-of-the-string/
	
	
13.BackTracking best practices -'all possible solution' in the question indicates that it is a backtracking problem. 
	-Sort the input before calling recursive function.
	-To avoid repeated combinations like [2,1,3] and [3,2,1] for original combination [1,2,3], for each index of current ans pick one element from source and permutate remaining with elements that come after chosen element in the source.Example if [1,2,3,4,5,6] is the source and the task is to generate all 3 digit combinations(repeatations not allowed).first pick one element from source say 3, then permuate remaining with [4,5,6].This sum can also be solved using method in 12 using combinations but that generates combinations of all length which is not efficient.reference:https://leetcode.com/problems/combination-sum-iii/description/
	-use boolean return type for problems that find only one existing solution.return true only if correct solution is found,if true is returned dont go for other permutations return true.if false is returned permutate with other values.This practice makes sure that if required solution is found program does not go for other permutions program control will immediately exit from the recursion tree(along the path).ref:https://leetcode.com/problems/sudoku-solver/description/
	
14.Infix,Prefix,Postfix-Stack problems
	-if the src is in prefix or postfix ,iterate it from operant side(prefix-right to left,postfix-left to right).
	For each iteration,if the character is operand then push it to stack.if the character is operand then pop two elements from the stack and form the notation(infix=(a+b)[do include '(' and ')'] ,prefix=+ab, postfix=ab+) and push this notation to stack. After the end of iteration pop the element from stack that is the answer.
	-if the src is in infix form then algorithm is slightly complex.
	
15.Monotonic Stack-Next Greater or Smaller elements
	-Most(almost every) of the monotonic problems can be solved by finding next greater or smaller element for each index(in any one or both sides)
	-If a problem involves iterating through all sections and finding answer for each section(answer for each section lies in the source), then the same problem can be solved by iterating over each element and finding the sections for which the current element is the answer.
		Example 1:Next Greater element-VVV Important(for each element find the next greater element)
			-General aproach:iterate through each element and find its next greater element.Time complexity O(n^2).
			-Using Stack(Monotonic stack):for each element find the other elements for which the current element is next greater element.The elements for which next greater elements need to known are present in stack(arranged in descending order from bottom to top).In each iteration do the following,If the current element is greater than top of stack then current element is the NGE for top of stack,pop the top and put top and current element to map(NGE for the top in right side is current element,if you want NGE on left side then after popping the element at the top of stack is left NGE ref:https://youtu.be/Dq_ObZwTY_Q?si=Dq_q66BcfJEJoglx).Do this until current element is less than top of stack or stack becomes empty.Add current element to top of stack(this means NGE for current element is not known at this point of time and NGE needs to be known in upcoming iterations).At the end of traverasal stack contains some elements,those elements don't have NGE.Time complexity-Each element is visited only once and pushed to the stack only once.Hence time complexity is O(n).Using this method you can find NGE of each element in both left and right side in single traversal using single stack.
				Key Points:(i) Every element is pushed to the stack and popped(Few elements which dont have right NGE are not popped but can be popped using seperate for loop).
				(ii) At the time when the element is popped ,left and right NGEs are known(This is correct point to perform operation on each element).
		Example 2 :Sum of subarray mins(Sum of minimums of all subarrays of given array)
			-Brute Force Approach :Iterate through all subarrays(O(n^2)) and find min for each one and add it to the sum.Time complexity -O(n^3 or n^2)
			-Optimal Approach:Iterate through each element and find all the subarays(sections) for which current element is the minimum.This involves finding next Smaller element for each element in left as well as right hand side, computing for each element can be done while popping it using method in Example 1(This reduces space complexity).
			
		Example 3:Largest rectangle in histogram
			-Brute Force:iterate through all possible rectangles and find the one with max area
			-Optimal Oproach :All rectangles that can be formed can have heights h where h =arr[i] for some i(h is an element in arr).
				-iterate through each element,find the area of largest rectangle that can be formed with height equivalent to current element.Area of largest rectangle with height arr[i]=arr[i]*(index of next smaller element in right side- index of next smaller element in left side-1).Now use the method in Example 1 to solve the sum.ref:https://leetcode.com/problems/largest-rectangle-in-histogram/submissions/1539197444/
		
		
		
16.Top k elements(Heaps)-get Top k largest elements in the array 
	-Approach 1:Sort the array in ascending order and retrieve last k elements.
	-Approach 2:Push all elements to the maxHeap.Then remove k elements from the heap(these elements are the required Answer).
	-Approach 3(Using min heap):The min heap maintains k largest elements.when adding new element, if new element is greater than root (smallest among the k elements) then remove root and add new element to the heap else do nothing.If the number of elements in heap is less than k,then dont compare with root directly add it to the heap.Add all elements to the heap using the above method ,at any heap contains k largest elements so far.
	-Approach 3(revised): The min heap maintains k largest elements.when adding new element,after adding check if(heap_size>k) if true then remove root(smallest among the k+1 elements).Add all elements to the heap using the above method ,at any heap contains k largest elements so far.For k smallest elements use MaxHeap.
